## Context

当前桌面端已有工具中心和视频工具，工具模块独立于阅读模块。Tauri Rust 侧已经集中处理本地目录访问、文件扫描、外部路径打开、日志记录和 SQLite 访问。Agent 会话清理涉及用户主目录下其他工具的数据文件，且不同 Provider 的本地存储结构、官方 CLI 能力和风险边界不同，因此需要把 UI 编排、状态管理和实际文件操作清晰分层。

## Goals / Non-Goals

**Goals:**

- 将 Agent 会话清理作为桌面端工具中心的独立工具接入。
- 前端负责筛选、确认、展示和结果反馈；Rust 侧负责真实扫描、备份、删除和日志记录。
- 用统一的数据模型描述 Provider、会话、dry-run 计划、备份结果和删除结果。
- 对不同 Provider 使用 adapter 策略，允许 Claude Code、Codex、OpenCode 的能力等级不同。
- 默认采用保守删除：先 dry-run，再由用户选择备份删除或永久删除；受保护数据永不删除。

**Non-Goals:**

- 不在 Web 端提供该工具。
- 不实现云端同步、远程 Agent 会话清理或跨设备清理。
- 不清理认证、配置、模型、MCP、偏好设置等非会话数据。
- 不承诺完全理解所有未来版本的 Provider 私有存储格式。

## Decisions

### Decision: 使用 Provider adapter 模型

为每个 Provider 定义检测、扫描、生成删除计划、创建备份、执行删除的 adapter。上层 UI 只依赖统一结构，不直接理解具体文件布局。

备选方案是把所有逻辑写在单个 Rust 命令里。该方案短期更快，但 Codex 和 OpenCode 的删除路径明显不同，后续扩展新 Provider 会让条件分支快速膨胀。

### Decision: 删除流程拆成 scan、plan、execute 三步

扫描只读取元数据；plan 只生成 dry-run；execute 必须引用 plan。默认执行路径会先创建备份；永久删除路径会跳过备份并记录不可恢复删除模式。这样 UI 可以在不可逆操作前展示完整影响范围，也方便测试错误路径。

备选方案是点击删除后立即执行。该方案不适合“硬删除”场景，用户无法确认具体会改哪些文件或记录。

### Decision: Rust 侧执行文件和数据库操作

真实文件系统访问、目录遍历、备份、SQLite 读取和外部 CLI 调用放在 Tauri Rust 命令中。前端通过 `api/agentSessions.ts` 和 composable 管理交互状态。

备选方案是在前端使用 Tauri fs API 直接操作。该方案需要扩大窗口权限，且更难集中实现路径保护和审计日志。

### Decision: OpenCode 优先官方 CLI，Codex 保守处理，Claude Code 优先官方项目级清理

OpenCode 有官方会话删除命令，优先调用 CLI。Claude Code 有项目级清理能力，第一版可以把它作为安全入口，并在 UI 明确影响范围。Codex 的本地结构包含会话文件、归档会话、索引和数据库，第一版必须避免删除整个根目录，必要时对不确定目标只生成计划并要求用户确认。

备选方案是直接按目录删除所有 Provider 会话文件。该方案会造成配置误删或索引不一致，不适合产品化工具。

### Decision: 备份使用 Docs Atlas 应用数据目录

备份保存到 Docs Atlas 应用数据目录下的专用子目录，并在删除结果里展示备份位置。备份结构保留 Provider、时间戳和会话标识，便于用户手动恢复。

备选方案是保存到原 Provider 目录旁边。该方案更接近源数据，但容易被后续清理误删，也可能污染 Provider 自身目录。

## Risks / Trade-offs

- Provider 存储格式变化 → adapter 必须把未知格式降级为只读或不可删除状态，并在 UI 显示原因。
- 删除运行中的会话可能导致 Provider 状态损坏 → 删除前检测常见进程；检测不到时仍要求用户确认已退出对应工具。
- Codex 索引或数据库处理不完整 → 第一版将 Codex 删除能力标记为高风险，默认要求备份并展示索引/数据库目标；永久删除必须由用户主动选择。
- 外部 CLI 不存在或版本不兼容 → Provider 状态展示为能力受限，允许用户打开数据目录但不伪装成可删除。
- 备份占用磁盘空间 → dry-run 展示预计备份大小，并允许用户先查看备份目录。

## Migration Plan

1. 新增工具入口和视图，不改变现有阅读、搜索、设置和视频工具行为。
2. 新增 Tauri commands，并保持现有命令签名不变。
3. 第一版默认启用 dry-run 和备份删除，同时提供明确标注的永久删除入口；永久删除跳过备份，仅在用户主动选择时执行。
4. 如发现 Provider adapter 行为异常，可在后续版本降级对应 Provider 的删除能力，不影响其他工具。
