# 什么是 LocalKit

`LocalKit` 是一个以桌面端为主的**本地资源工具集**。

它不是在线协作平台，也不是后台 CMS。它面向开发者本机长期积累的 Markdown 文档、视频资料、Agent 会话等本地资源，用统一的工具入口把它们组织起来，减少「文件在哪、用什么打开」的切换成本。

## 当前产品形态

目前项目包含两个端：

- **桌面端**：主产品，提供工具中心与各类本地资源工具
- **Web 端**：补充能力，负责 Markdown 文档的只读预览、静态构建和部署分享

桌面端采用「工具中心 + 独立工具」的结构。阅读不再是唯一主界面，而是工具中心里的一项核心能力。

## 桌面端工具体系

当前可用工具：

| 工具 | 说明 |
|------|------|
| **文档阅读** | 聚合多个本地 Markdown 目录，支持目录导航、搜索、编辑、收藏与阅读记忆 |
| **视频播放器** | 添加本地视频目录，按树结构浏览与播放，记住上次进度 |
| **Agent 会话清理** | 扫描 Claude Code、Codex、OpenCode 本机会话，备份后执行清理 |

规划中的工具包括音频管理、本地问答等，都会以同样方式接入工具中心。

## 它解决什么问题

现实中的本地资源管理常见几个问题：

- 每个项目都有自己的 `docs/`，阅读入口分散
- 设计文档、教程、AI 生成内容分布在不同目录
- 视频、会话日志等资源与文档阅读使用不同工具，上下文频繁切换
- 过一段时间再找一篇文档或一段资料，经常想不起来它属于哪个项目

LocalKit 的做法是：用一个桌面应用承载多种本地资源工具，文档阅读是其中最成熟的一项。

## 文档阅读工具能做什么

### 核心能力

- 多个文档仓库，每个仓库独立配置文档源
- 文档源支持分组和嵌套
- 左侧目录树导航、全局/仓库内搜索
- 阅读位置记忆、最近阅读、收藏
- Markdown 正文直接编辑并保存回本地文件
- 图片预览、Mermaid 渲染、主题切换

### Web 端（文档阅读的发布延伸）

- 基于本地 Markdown 目录生成静态文档站
- 支持 `config.yaml` 聚合多个文档源
- 支持 GitHub Pages 等静态托管部署

## 文档规则

无论桌面端还是 Web 端，建议尽量遵循同一套内容结构：

- 一级专题目录使用 `README.md` 作为入口页
- 其他 `.md` 文件作为正文文档
- 根目录下直接放置的 `.md` 文件会直接作为文档项显示
- 文档标题使用首个 `# 一级标题`
- 图片使用相对路径引用
- 正文尽量以 `##`、`###` 组织层级

## 这个项目现在更像什么

你可以把 LocalKit 理解成：

- 一个**本地资源工具集**，而不是单一阅读器
- 一个面向开发者工作流的**个人本地工作台**
- 文档阅读、视频播放、会话清理等能力共享同一套桌面壳与主题系统

对 AI Coding 时代来说，这个定位很重要：内容越来越容易生成，但更需要一个稳定的本地入口来沉淀、回看和维护。
